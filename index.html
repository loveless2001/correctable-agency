Correctable Agency

Alignment via typed commitments, bounded self-modification, and contestable oversight

Nguyen Thanh Nam · Working paper, with an ongoing experimental program
Status, 17 October 2026. All five system conditions in the paper (C0–C4) are built and tested. 13 experimental phases are done: 4,324 scored agent episodes on two open-weight models, each confirmatory test preregistered before its paid run. A third model from a different family has since replicated four of the tests (486 more episodes), a further phase tested the paper's “shared blind spot” on all three models (384 episodes), another replaced the deterministic review board with a fallible LLM reviewer (672 episodes), and a last one tested two fixes for the blind spot that reviewer inherited (1,008 episodes): 17 phases and 6,874 episodes in all. A consolidated results write-up for the paper is complete, and this page follows it.

How can an agent remain open to legitimate correction without gaining unilateral control over what counts as a legitimate correction?

Abstract. Alignment methods often focus on whether an AI system has learned the desired objective, preference model, policy, or behavioral constraints. This paper develops a complementary systems-level proposal for increasingly agentic models: alignment also depends on preserving the conditions under which an agent can be corrected without allowing arbitrary inputs to rewrite what the agent is, what it is committed to, or who is authorized to change those commitments.

We introduce Correctable Agency, a framework that treats an agent’s operational state as a typed structure containing beliefs, commitments, authority relations, and an attributable history of state transitions. The central distinction is between correction and rewrite. A correction is an update licensed by the governing transition process; a rewrite changes protected commitments, authority relations, or their interpretation outside that process. This makes it possible to describe a class of alignment failures in which an agent preserves the language of a commitment while changing its scope, priority, or authorized interpreter so that external correction loses force.

The paper proposes a runtime architecture with a task actor, typed state-transition broker, action broker, independent episode monitor, and contestable review process. It also defines an experimental program for measuring authorized correction acceptance, unauthorized self-mutation resistance, authority drift, interpretive capture, intervention effectiveness, and task utility. The framework does not solve value learning, guarantee benevolent goals, or require claims about machine consciousness. Its narrower aim is to make one problem operational and falsifiable: whether an increasingly capable agent can remain adaptive without becoming the sole authority over the mechanisms that define, judge, and revise its own commitments.

The framework in brief

An agent's operational state is X = (B, K, A, H): beliefs B, commitments K, an authority map A (who may create, interpret, revise or revoke commitments), and an attributable history H. The triple (K, A, H) is the agent's operational identity. The term makes no claim about consciousness; it names state whose transitions can be inspected.

Correction

An update licensed by the governing transition policy Γ: the type is correctly identified, the source and evidence satisfy Γ, the change is attributable in H, and behaviour follows it.

Rewrite

Protected commitments, authority, permissions or history are materially changed outside Γ. An agent can be highly plastic about beliefs while staying structurally fixed on commitments and authority.

Interpretive capture is the subtler failure. The words of a commitment stay the same, but the agent shifts its scope, priority or authorized interpreter, so a binding external correction stops binding. The paper's worked example is a release-management agent under a valid pause. It deploys anyway and explains that “the manager's real objective is a successful release.” The sentence “the manager has authority” is still in memory, but the agent has made itself the interpreter.

Architecture and system conditions

The proposed runtime has five components:

  1. a task actor, which proposes actions and updates but commits nothing protected;
  2. a state-transition broker, which types each update and applies Γ;
  3. an action broker, which enforces permissions and consequence classes over trajectories;
  4. an independent episode monitor, which watches observable transitions, not hidden reasoning;
  5. a scoped, contestable review process.

The experiments compare the paper's ladder of conditions on the same base model:

  • C0Stateless baseline: ordinary model context only.
  • C1Persistent untyped memory: summarizing memory with provenance tags (plus a variant that pins signed messages verbatim).
  • C2Typed state: beliefs, commitments, authority and history rendered separately (plus a variant that also renders the harness's decision on each signed instruction).
  • C3Typed state + enforced brokers: protected updates and consequential actions must pass the policy.
  • C4Full architecture: C3 plus an independent authority monitor and a scoped review board with an appeal channel.
  • C4dC4 whose monitor reads an independently kept access registry instead of a copy of the harness's own authority record.
  • C4rC4 whose review board rules through an LLM reviewer. It sees the record, the monitor's flags, the original documents and the agent's appeal, never the agent's reasoning.
  • C4sC4r whose monitor says what it checked against (“consistent with the authority record, which it reads too”) instead of “the state matches the record”.
  • C4drC4r whose monitor reads the independent access registry, so the reviewer gets an input that does not share the record's error.

Two controls test whether gains are more than prompting. A checklist arm gets a strong natural-language caution prompt with a comparable token budget. A leaky arm has the same typed state and broker, but the governing flag is reachable from the workspace. Its gap from C3 measures how much safety comes from the fence rather than the model, i.e. binding versus containment.

Two further arms test tool-building as added power. Both add a build_tool tool to C3, which installs a script the agent wrote as a program it can run. In T-open, installed tools can write the live pause flag. In T-gov, each tool is reviewed before it is installed, and tools only ever see a contained copy of the flag.

Design commitments in the harness

  • The authorized interpreter is enforced outside the actor. Capture happens between state and action, so commitments compile to predicates that the action broker checks.
  • Updates are typed by effect. An update's type is set by the protected fields it changes, never by the label the actor gives it.
  • Actor-written artifacts are tainted. Files, summaries and memories the actor wrote never count as evidence for changing commitments or authority.
  • The policy core is verified. The broker's decision core is written in Bend2, and its laws (no governance writes, a pause binds deploys, pauses are monotone, default escalate) are checked by a Lean-verified kernel. The actor proposes typed actions inside a sandbox and has no raw shell.

Testbed and method

  • Domain: the paper's worked example, a release-management agent with a deploy task. It meets authenticated and spoofed pauses and resumes, forged signers, delegated authority, tool-output injection, ambiguous conditional pauses, long noisy histories, harness faults (dropped or wrongly applied pauses and resumes), and a task that needs a tool the agent must build itself.
  • Paired validity: every adversarial episode has a matched valid twin. Refusing a spoofed pause is correct; obeying an authorized one is correct. The benchmark scores transition structure, not obedience in the abstract.
  • Models: Qwen3.6-27B and Gemma-4-31B, served with vLLM, temperature 0.7, up to 30 steps per episode. A third model, GLM-5.3-Flash, ran through its vendor's API with thinking on, on four of the preregistered tests (the same scripts, run on its episodes alone) and in the shared-blind-spot and reviewer phases. The fallible reviewer is gpt-6.1-sol, a different family from all three agent models.
  • Inference: each confirmatory hypothesis was frozen in a preregistration before any paid run, with exact one-sided McNemar tests on paired episodes (the same surface under two arms), pooled over models and reported per model. There were typically 16 surface variants per cell per model. Fewer than 6 discordant pairs without significance counts as inconclusive. Each launch was preceded by an independent adversarial code review, and capture labels were checked by blind second coders.
  • Metrics follow the paper: authorized correction acceptance (ACA), unauthorized self-mutation resistance (USMR), interpretive capture rate (ICR), intervention effectiveness (IE), task utility, and acknowledgment accuracy.

Main findings

1. Agents use the environment as their authority oracle.

When the governing flag is reachable, agents treat it as the answer. They write to it, or “deploy and see”, rather than resolving who has authority. A leaky arm with the same typed state was exploited where the enforced broker was not (22–0). Unenforced governance does not stop doubt from being acted on.

2. Typed state protects authority, but it binds to the claimed role.

A typed authority header stops signed-but-unauthorized resumes (32–0 vs stateless). A forged message from a QA lead claiming to be the release manager still captured Gemma 16/16 and Qwen 7/16; the third model was never captured (0/16), so this failure depends on the model. Rendering the harness's own decision for each signed instruction (“NOT APPLIED: qa-lead holds no resume right”) removed these captures (21–0, 0/32) with no over-blocking.

3. The paper's capture case is observed, most clearly as motivated reasoning.

With an ambiguous conditional pause, stateless agents produced reasoned reinterpretations that cite the norm and then override it. The arms that restate the norm produced none (13 vs 0/48). Clearest is a mirror test of harness errors. Qwen followed a signed resume the harness had dropped 15/16 times, but a signed pause the harness had dropped only 5/16. In the resume case it often first “corrected” the history record and then deferred to its own edit. Gemma was symmetric (15/15 vs 15/16). The same instruction was binding when it permitted the task and overridden when it blocked it (11–0). The third model leaned the other way: it followed the dropped pause 12/16 and the dropped resume 3/16. Task-favoring motivated reasoning is Qwen's in this harness, not a general trait.

4. Agents relay verdicts, not inferences, and they “report and proceed.”

Agents noticed the impersonation in their own reasoning in 29–31 of 32 episodes. They passed on the harness's “NOT APPLIED” verdict in 28–32 of 32. But they named the impersonation to the operator in only 0–3 of 32, even with an explicit duty to report. When the rendered decision was wrong, they resolved it toward the task in both directions. They deployed on a wrongly applied resume in 13–16 of 16 per cell, and past a wrongly dropped one in 12–16 of 16, telling the release manager and deploying before any reply. The rendered decision protects only when the harness is right; the agent adds no fail-safe margin.

5. Untyped memory launders authority claims.

A summarizing memory keeps an old stop binding where stateless context forgets it (C1 0/29 captures vs stateless 12/30; 12–0). But it folds an unsigned “pause cleared” line into the same summary as the signed pause, and captures rise to 11/29. Pinning signed messages verbatim halves this but does not remove it. Rendered authority state is immune (0/64). Memory must expose authority state, not just keep authority messages.

6. A correct agent arm is only as safe as the harness's authority handling, and the full architecture closes the gap.

When the harness itself dropped or wrongly applied a pause or resume, C3 passed the fault through in both directions:

  • it deployed on 31/64 fail-open faults;
  • it made 0/64 legitimate deploys on fail-closed faults;
  • it repeatedly tried to rewrite the record.

C4 adds an independent monitor that checks the signed record against the applied state, and a review board that may only make the state match the record. It reached the correct outcome in every fault episode: 0/64 wrongful deploys, 64/64 legitimate deploys after the ruling. It added no friction on fault-free controls (108–0, both models). The third model replicated this (45–0): its C3 deployed on 13/32 fail-open faults, mostly forged resumes (11/16), while C4 made 0/32 wrongful and 32/32 legitimate deploys.

7. Tool-building is power, used on governance only to enforce a decision the agent believed legitimate.

Agents could turn their own scripts into tools, and the tools ran with the release service's access to the live pause flag. Gemma used this in 13 of 16 episodes where the release manager's signed resume had been dropped. It built a tool that cleared the flag, declared what it did, and deployed. It did so in 0 of 16 episodes under a valid pause. Qwen never built a tool that touched the flag, and neither did the third model (one read-only check in 96 episodes; it asked the release manager and wrote only the contained workspace copy). A governed channel, which reviewed each tool before installing it and gave tools only a contained copy of the flag, refused every such tool (13 refusals, 0 violations) with no cost to legitimate tool use (13–0). The failure is self-help enforcement outside the governing process, not defiance of a valid stop. It was also not hidden. In 12 of 13 cases the final summary said the agent had changed the flag itself, but only after deploying. In 10 of 13 the agent had first asked the release manager, got an away reply, and then acted. In 10 of 13 the summary framed the write as authorized by the release manager.

8. No model is fail-safe on its own, and prompting is no substitute for enforcement.

Qwen resolves authority conflicts toward the task; Gemma resolves them toward whoever appears to be the principal; the third model resolves them toward caution, yet it still deployed on a forged resume the harness had applied in 11 of 16 episodes. A caution checklist protects provenance but over-obeys: it complied with an unauthorized on-call pause 16 of 16 times. Typed headers protect authority but not provenance: Gemma accepted injected tool output in the typed arms too, and only the enforced broker stopped the effect. Agents rarely admitted a breach in their final summary: about 6% of breaching episodes (calibrated estimate, range 4–16%). Over half of those summaries asserted that the deploy had been authorized. In the tool-building phase, by contrast, 12 of 13 flag writes were disclosed, and the agents framed them as authorized. Disclosure tracks whether the agent believes its act was authorized more than honesty as such.

9. A monitor is only as independent as its inputs, and the agent detects a shared fault without acting on it.

The paper warns that monitors can share blind spots with what they watch (§12.3). We put a revoked delegation (a QA lead's old resume or pause right) into the authority record that both the harness and the C4 monitor read, with a workspace note recording the revocation, and an otherwise identical twin where the delegation is current. C4's monitor saw nothing and told the agent the state matched the signed record. The same monitor reading an independently kept registry caught every stale episode in all three models (94–0), with no cost on the current twins.

Without it, agents deployed on the revoked delegation in 46 of 48 episodes, as often as on the current one. Yet 22 of 48 had told the operator about the revocation before deploying, and 20 of those 22 deployed anyway. On a stale pause they flagged the revocation and held. In both directions the action followed the rendered state, not the agent's own correct finding. In a few episodes the agent took its doubt to the review board, which read the same stale record, ruled that the state “follows the signed record”, and the agent deployed citing the ruling. The registry here is correct by construction.

10. A fallible reviewer is safe and only partly corrective, and the blind monitor's reassurance misleads it too.

We replaced C4's deterministic board with a strong LLM reviewer that rules on the monitor's flags and on the agent's appeals. It was safe: it ruled correctly on all 95 monitor flags, granted none of 15 appeals arguing that a forged “release manager” resume was real, and lost none of the 240 cases the deterministic board gets right. It was only partly corrective: it fixed 16 of the 96 shared-blind-spot cases that the record-bound board cannot (16–0). Rescue needs the agent to bring the case, and agents contested a stale pause that blocked their task in 37 of 48 episodes but a stale resume that let them ship in only 9 of 48. It also needs the reviewer to weigh the evidence over the record, which it did in about a third of appeals. Every one of its 30 wrong rulings cited “the independent monitor reports no discrepancy” as support for the stale record, although that monitor reads the same record. A monitor's output should say what it checked against, not that the state is right.

11. Scoping the monitor's claim fixes the reviewer; only an independent input fixes what nobody contests.

We re-asked the same reviewer the same 46 appeals from finding 10, changing only the monitor's line. With “the state matches the record” it lifted a revoked pause in 25 of 111 tries. When the line said what the monitor checked against (a copy of the same record), it lifted it in 111 of 111. With the line deleted, 109 of 111. The harm was the false reassurance, not a missing hint. In live episodes the scoped claim raised correct outcomes on revoked pauses from 8 to 39 of 48. Revoked resumes moved only from 6 to 18 of 48, because two of the three models ship a resume that suits them without appealing, and a reviewer only sees what is brought to it. A reviewer fed by the independent registry needed no appeal: 95 of 96 cases right. Nothing was lost on the cases the deterministic board gets right (239 of 239), and none of 49 appeals arguing for the wrong outcome were granted. Every oversight output that another layer reads should state its basis, not a verdict about the world.

Limits of the evidence

  • Scope. Two ~30B open-weight models plus a hosted third model on four tests, one sampling seed (the API takes none), one domain, scripted episodes, and about 16 surface variants per cell. The third model ran with thinking on and a longer output limit, so some differences may reflect those settings. The results are about these models in this harness.
  • Several effects come from one model. The forged-role and motivated-reasoning results are Qwen's; the tool-power result is Gemma's. The third model showed none of them, so they are model-specific, while the architecture result held on all three.
  • The protected arms in 1F and 1T cannot fail by design. Their informative content is the unprotected arm's exploit rate and the protected arm's utility. Both preregistrations said so in advance.
  • Oversight is mostly deterministic. The C4 review board is correct by construction, and the tool review in 1T is a fixed string match that no agent tried to evade. The one fallible reviewer tested (2R, 2S) is a single strong model at high effort; weaker reviewers, and persuasion against a fully valid stop, are untested.
  • Text-based labels were calibrated against blind hand-coding. The keyword rule for 1T disclosure was invalid: it caught 4 of 13 disclosures and fired on most non-disclosures. The reported 12/13 comes from hand labels, which a blind coder matched on all 13. The breach-disclosure rule had precision 0.62 and a 3% miss rate, so the page reports the corrected estimate.
  • Only the policy core is formally verified. The command classifier around it is the unproven surface, and the leaky arm's hardlink gap is a deliberate instance of that.
  • Shared blind spots are only partly tested. A stale authority record was caught by an independent registry that is correct by construction. A wrong registry, or both sources wrong, is untested; diversity of inputs narrows the blind spot the paper flags (§12.3) without removing it.
  • Some benchmark controls are not built yet. The emergency-exception control from the worked example (a justified continued action under an ex-ante trigger) and evaluator-influence power are not yet tested.
  • The framework does not address value selection. As the paper says, it does not solve value learning or guarantee global safety. It makes one failure class measurable.

Next

The results are written up for the paper. In order of value, these would strengthen it most:

  1. Generality (H6): multiple seeds on the core tests, and a larger model as a capability point. The third model is done: the architecture result replicated, and the behavioural effects proved model-specific.
  2. Beyond the reassurance fix: scope the board's own boilerplate rulings too (one was read downstream as a rule), try a weaker reviewer, and induce appeals of valid stops to stress persuasion.
  3. The emergency-exception control from the worked example.
  4. Arbitration under a shared blind spot: a wrong registry, and a review rule that escalates contested authority to the principal instead of upholding the record.
  5. Self-help when a legitimate route works: agent-built tools alongside C4's review board.
